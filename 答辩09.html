01 架构怎么读：1 个协同核心 + 端云双脑 + 3 类感知输入 + 4 项平台支撑 先找大脑，再看派单

端云协同为核心；端侧 Master 负责低时延、离线可完成的意图识别与控制，云侧 Master 负责复杂意图编排、跨服务协同与长期记忆；语音（声纹）+ 视觉（DMS/OMS）+ 车身数据三维感知；芯片适配 / DAG 编排 / S2S 情感语音 / TI-One 四项支撑。子 Agent 各自拥有独立记忆空间、相互隔离是 2.0 的核心架构升级。

02 能力 vs 边界：升级了体验，没突破天花板 本次最大洞察

2.0 真升级：TTS 更拟人 · 并行任务（ASR 与执行解耦） · 反应快很多。但能力边界没变 —— 根因是微信小程序框架受沙箱、页面结构暴露程度与主动交互权限限制，难以稳定获取可操作元素、坐标与主动点击能力，只能模拟人操作走写死路径，页面一改版就得人工后台改。

03 两条路径的取舍：GUI 模拟 vs API 直连 能上 API 就上 API

路径 A 小程序 GUI 模拟：覆盖面广（电影/生活/出行，当前主流），但对页面改版敏感、稳定性与可审计性较弱。路径 B API 后台直连：需逐家完成商务与接口接入，但链路更稳定、可明确授权与结果确认，目前仅瑞幸/麦当劳/肯德基三家（未来主攻）。生活类场景可用 GUI 作补充。

04 放回竞争格局看：边界是选出来的 战略选择 ≠ 能力短板

腾讯当前战略是「尊重边界：不碰车控」，座舱领域以生态服务、智能体、地图内容及云能力为核心定位，不以自研整车操作系统作为主攻路径，用生态独占 + 开放接口换更广连接。斑马能细粒度调用，是因为 AliOS 与支付宝小程序同属阿里系、权限自主 —— 差距在「权限链」，不在技术水平。三家 Agent 架构已趋同（都是 1 总控 + N 垂域）。

商业模式

腾讯只做方案 → 卖给 OEM 主机厂 → OEM 再卖终端用户，按「每辆车 License」计费。

所以客户要的不是「做好的功能」，而是可自由拼装的原子化能力 —— 行业风向也已从「原子能力更多」转向「原子能力好不好组合」
微信生态构成腾讯座舱的重要差异化优势，但其开放边界也决定了部分 Agent 能力的实现上限。
